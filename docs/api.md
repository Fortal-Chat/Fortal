# Договор API — v1

> Меняется **только** через Pull Request, который одобрили оба.
> Клиенты, пока сервер не готов, работают с заглушками по этому документу.

## Общее

- Формат: JSON, кодировка UTF-8, `Content-Type: application/json`.
- Время: строка ISO 8601 в UTC, например `"2026-11-07T12:00:00Z"`.
- ID: строка (UUID), например `"7f1c…"`.
- Имена полей: `snake_case` (`owner_id`, `created_at`).
- Поле, у которого нет значения, передаётся как `null`, а не пропускается.
- Строки из запросов сервер обрезает по краям (`trim`) до проверки длины.

### Адреса (dev)

| Сервис | Порт | Пример |
|---|---|---|
| Сервер (Spring Boot), HTTP | 8080 | `http://localhost:8080` |
| Gateway, WebSocket | 8081 | `ws://localhost:8081/` |

### Авторизация

Все эндпоинты, кроме `GET /health`, `POST /auth/register` и `POST /auth/login`, требуют заголовок:
```
Authorization: Bearer <JWT>
```
Токен выдаётся при регистрации и входе и действует 7 дней. Обновления токена пока нет. Выход — только на клиенте: клиент забывает токен.

### Ошибки

Любой ответ 4xx/5xx имеет тело:
```json
{ "error": { "code": "invalid_credentials", "message": "Неверный логин или пароль" } }
```
`code` — стабильный машинный код, по нему клиенты выбирают текст и реакцию. `message` — для человека, может меняться.

Общие коды, которые может вернуть любой эндпоинт:

| HTTP | `code` | Когда | Что делает клиент |
|---|---|---|---|
| 400 | `validation_error` | тело не JSON, нет поля, не проходит правила | показывает ошибку формы |
| 401 | `unauthorized` | нет токена, токен неверный или истёк | забывает токен, открывает экран входа |
| 403 | `forbidden` | участник сообщества, но действие только для владельца или автора | показывает «Недостаточно прав» |
| 404 | `not_found` | объекта нет **или** пользователь не участник его сообщества | показывает «Не найдено» |
| 500 | `internal_error` | ошибка на сервере | показывает «Ошибка сервера» |

Неучастнику сервер отвечает `404`, а не `403`, чтобы не выдавать, что сообщество существует. Некорректный UUID в пути — тоже `404 not_found`.

### Списки

Списки всегда приходят объектом с полем `items`, а не голым массивом:
```json
{ "items": [ ... ] }
```
Так в список можно добавлять поля (например, `has_more`), не ломая клиенты.

## Объекты

### `User` — текущий пользователь
```json
{ "id": "uuid", "username": "alice", "email": "alice@example.com", "created_at": "2026-11-07T12:00:00Z" }
```

### `PublicUser` — другой пользователь
```json
{ "id": "uuid", "username": "alice" }
```
`email` других пользователей не показывается никогда.

### `Community` — сообщество
```json
{ "id": "uuid", "name": "Fortal Team", "owner_id": "uuid", "created_at": "2026-11-07T12:00:00Z" }
```

### `Member` — участник сообщества
```json
{ "user": { "id": "uuid", "username": "alice" }, "role": "owner", "joined_at": "2026-11-07T12:00:00Z" }
```
`role`: `owner` или `member`. Владелец у сообщества ровно один.

### `Channel` — канал
```json
{ "id": "uuid", "community_id": "uuid", "name": "general", "type": "text", "position": 0, "created_at": "2026-11-07T12:00:00Z" }
```
`type` пока всегда `text` (голосовые каналы — этап 8). `position` — порядок в списке, начиная с 0.

### `Invite` — приглашение
```json
{ "code": "aB3xK9pQ", "community": { "id": "uuid", "name": "Fortal Team" }, "expires_at": "2026-11-14T12:00:00Z" }
```
`code` — 8 символов `[A-Za-z0-9]`. Действует 7 дней, число использований не ограничено.

### `Message` — сообщение (этап 3)
```json
{
  "id": "uuid",
  "channel_id": "uuid",
  "author": { "id": "uuid", "username": "alice" },
  "content": "привет",
  "created_at": "2026-11-07T12:00:00Z",
  "edited_at": null
}
```

## HTTP (сервер)

### Служебное

#### `GET /health`
Проверка, что сервер жив. Без токена.

`200`
```json
{ "status": "ok" }
```

### Регистрация и вход (этап 1)

#### `POST /auth/register`
Без токена.
```json
{ "username": "alice", "email": "alice@example.com", "password": "secret123" }
```
Правила:
- `username`: 4–32 символа: латиница, цифры, `_`, `.` и `-` (`^[a-zA-Z0-9_.-]{4,32}$`);
- `email`: корректный адрес;
- `password`: 8–72 символа: латиница, цифры и символы `_ . - ? / \ % * @ $ # ~ ! ( )` (`^[a-zA-Z0-9_.?/\\%*@$#~!()-]{8,72}$`). Пробелы, кириллица и другие символы не допускаются.

`username` и `email` уникальны **без учёта регистра**: если есть `Alice`, зарегистрировать `alice` нельзя. Регистр, который ввёл пользователь, сохраняется и показывается как есть.

`201`
```json
{ "user": { "id": "uuid", "username": "alice" }, "token": "<JWT>" }
```
Ошибки: `400 validation_error`, `409 username_taken`, `409 email_taken`.

#### `POST /auth/login`
Без токена.
```json
{ "login": "alice", "password": "secret123" }
```
`login` — username или email, ищется без учёта регистра.

`200` — тело как у `/auth/register`.
Ошибки: `400 validation_error`, `401 invalid_credentials`.

#### `GET /users/me`
Текущий пользователь по токену. Клиент вызывает его при запуске, чтобы проверить сохранённый токен.

`200` — `User`.
Ошибки: `401 unauthorized`.

### Сообщества (этап 2)

#### `POST /communities`
Создать сообщество. Создатель становится владельцем, сервер сразу создаёт в нём канал `general`.
```json
{ "name": "Fortal Team" }
```
Правила: `name` 2–100 символов.

`201` — `Community`.
Ошибки: `400 validation_error`.

#### `GET /communities`
Сообщества, в которых состоит пользователь, по дате вступления, от старых к новым.

`200`
```json
{ "items": [ Community, ... ] }
```

#### `GET /communities/{id}`
`200` — `Community`.
Ошибки: `404 not_found`.

#### `PATCH /communities/{id}`
Переименовать. Только владелец.
```json
{ "name": "Новое имя" }
```
`200` — `Community`.
Ошибки: `400 validation_error`, `403 forbidden`, `404 not_found`.

#### `DELETE /communities/{id}`
Удалить вместе с каналами, участниками, приглашениями и сообщениями. Только владелец.

`204` — без тела.
Ошибки: `403 forbidden`, `404 not_found`.

### Участники (этап 2)

#### `GET /communities/{id}/members`
Все участники: сначала владелец, дальше по дате вступления. Постраничной выдачи пока нет.

`200`
```json
{ "items": [ Member, ... ] }
```
Ошибки: `404 not_found`.

#### `DELETE /communities/{id}/members/me`
Выйти из сообщества.

`204`.
Ошибки: `404 not_found`, `409 owner_cannot_leave` (владелец может только удалить сообщество).

#### `DELETE /communities/{id}/members/{user_id}`
Исключить участника. Только владелец, себя исключить нельзя.

`204`.
Ошибки: `403 forbidden`, `404 not_found`, `409 owner_cannot_leave` (если `user_id` — сам владелец).

### Приглашения (этап 2)

#### `POST /communities/{id}/invites`
Создать приглашение. Может любой участник. Тело пустое.

`201` — `Invite`.
Ошибки: `404 not_found`.

#### `GET /invites/{code}`
Посмотреть, куда ведёт приглашение, до вступления. Может любой пользователь с токеном.

`200` — `Invite`.
Ошибки: `404 invite_not_found` (нет такого кода или срок истёк).

#### `POST /invites/{code}/accept`
Вступить в сообщество. Тело пустое.

`200` — `Community`.
Ошибки: `404 invite_not_found`, `409 already_member`.

### Каналы (этап 2)

#### `GET /communities/{id}/channels`
Каналы сообщества по `position`.

`200`
```json
{ "items": [ Channel, ... ] }
```
Ошибки: `404 not_found`.

#### `POST /communities/{id}/channels`
Создать канал в конце списка. Только владелец.
```json
{ "name": "random" }
```
Правила: `name` 1–32 символа, только `[a-z0-9_-]`. Имя уникально внутри сообщества.

`201` — `Channel`.
Ошибки: `400 validation_error`, `403 forbidden`, `404 not_found`, `409 channel_name_taken`.

#### `PATCH /channels/{id}`
Переименовать. Только владелец сообщества.
```json
{ "name": "offtopic" }
```
`200` — `Channel`.
Ошибки: `400 validation_error`, `403 forbidden`, `404 not_found`, `409 channel_name_taken`.

#### `DELETE /channels/{id}`
Удалить вместе с сообщениями. Только владелец сообщества. Остальные каналы сдвигаются, чтобы `position` шли подряд.

`204`.
Ошибки: `403 forbidden`, `404 not_found`.

### Сообщения (этап 3)

#### `GET /channels/{id}/messages?before=<message_id>&limit=50`
История канала, **от новых к старым**.
- без `before` — самые новые;
- `before` — сообщения старше указанного (для подгрузки при прокрутке вверх);
- `limit` — 1–100, по умолчанию 50.

`200`
```json
{ "items": [ Message, ... ], "has_more": true }
```
`has_more: false` — дальше сообщений нет.
Ошибки: `400 validation_error` (кривой `limit`), `404 not_found` (нет канала или `before` не из этого канала).

#### `POST /channels/{id}/messages`
```json
{ "content": "привет" }
```
Правила: `content` 1–2000 символов.

`201` — `Message`.
Ошибки: `400 validation_error`, `404 not_found`.

#### `PATCH /messages/{id}`
Изменить текст. Только автор. Сервер ставит `edited_at`.
```json
{ "content": "привет всем" }
```
`200` — `Message`.
Ошибки: `400 validation_error`, `403 forbidden`, `404 not_found`.

#### `DELETE /messages/{id}`
Удалить. Автор или владелец сообщества.

`204`.
Ошибки: `403 forbidden`, `404 not_found`.

## Gateway (WebSocket)

Подключение: `ws://<host>:8081/`. Каждое сообщение — текстовый кадр с JSON вида:
```json
{ "op": "<операция>", "d": <данные или отсутствует> }
```

### Сервер → клиент: `hello`
Отправляется сразу после подключения.
```json
{ "op": "hello", "d": { "heartbeat_interval": 30000 } }
```
`heartbeat_interval` — как часто (мс) клиент должен слать `ping`.

### Клиент → сервер: `ping` → ответ `pong`
```json
{ "op": "ping" }
```
```json
{ "op": "pong" }
```

### Клиент → сервер: `echo` (только v0, для проверки связи)
```json
{ "op": "echo", "d": { "text": "привет" } }
```
Ответ — те же `d`:
```json
{ "op": "echo", "d": { "text": "привет" } }
```

### Сервер → клиент: `error`
```json
{ "op": "error", "d": { "code": "unknown_op", "message": "..." } }
```
Коды: `bad_json`, `no_op`, `unknown_op`.

### Черновик этапа 4 (уточняется перед началом этапа)

**Вход.** После `hello` клиент отправляет токен:
```json
{ "op": "identify", "d": { "token": "<JWT>" } }
```
В ответ:
```json
{ "op": "ready", "d": { "user": PublicUser } }
```
Если токен неверный — `error` с кодом `invalid_token`, после чего gateway закрывает соединение. Пока нет `identify`, события не приходят.

**События.** Сервер публикует их в Redis после успешного HTTP-запроса, gateway рассылает участникам сообщества. В `d` лежит тот же объект, что вернул HTTP.

| `op` | `d` | Кому |
|---|---|---|
| `message_create` | `Message` | участникам сообщества |
| `message_update` | `Message` | участникам сообщества |
| `message_delete` | `{ "id", "channel_id" }` | участникам сообщества |
| `channel_create` / `channel_update` | `Channel` | участникам сообщества |
| `channel_delete` | `{ "id", "community_id" }` | участникам сообщества |
| `community_update` | `Community` | участникам сообщества |
| `community_delete` | `{ "id" }` | участникам сообщества |
| `member_join` | `{ "community_id", "member": Member }` | участникам сообщества |
| `member_leave` | `{ "community_id", "user_id" }` | участникам сообщества и самому ушедшему |

Формат сообщений в Redis между сервером и gateway описывается отдельно перед этапом 4.
